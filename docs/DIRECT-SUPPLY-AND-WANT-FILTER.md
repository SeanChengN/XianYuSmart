# 直接入库与想要人数筛选

商机发掘可多选后点击“加入货源库”，保留搜索列表和第一步；“下一步：整理商品”继续使用原采集流程。全站比价的单件入库按钮位于“查看原商品”下方。单次最多 50 件，完成提示“新增 X 件，已有 Y 件”。

直接入库仅保存搜索资料，以及服务端同租户、同账号、同商品的有效规格缓存，不请求闲鱼搜索、详情、卖家信息或下单接口。浏览器提交的规格不受信任；服务重启后没有服务端缓存时，新货源保存为 `SEARCH_ONLY`，以后可手动获取规格。JSON 不填默认库存；货源表必填库存字段用 0 表示未配置。现有货源不会被覆盖，包括原账号、编辑内容和规格。

接口 `POST /api/merchant/opportunities/supply` 接收 `xianyuAccountId` 和 `candidates`，返回 `addedCount`、`existingCount`、`items[{itemId,supplyId,status}]`，状态为 `ADDED` 或 `EXISTS`。沿用运营菜单和运营写权限，验证账号归属，按租户和商品 ID 查重。直接入库事务锁住租户用户行，随后使用当前读查询货源，避免两个直接入库请求在 MySQL 重复读下重复新增。批次内重复商品仅插入一次。其他既有写入路径仍保留原行为。

两个页面支持最低想要人数、综合匹配、价格升降序、想要人数升降序。全站比价仍支持价格区间，搜索展示价统计随筛选结果变化。所有筛选仅作用于已加载商品，不请求或加载其他结果。最低人数启用时排除缺失和异常标签；输入非负整数，包括 0。`879人想要`、`1.2万人想要`、`约1.2万+人想要` 按显示数字比较，原标签不改写。缺失人数始终排最后，同值保持原顺序。

商机列表筛选会取消隐藏商品的选择；排序保留可见选择。新条件沿用用户、账号、页面隔离的搜索缓存，旧缓存可恢复，仍不保存选择、草稿和步骤。非法人数输入有明确提示，不写入缓存破坏上次搜索记录。

App 上的“已售3万+”与 Web 数据源不同，现有 Web 搜索样本没有可靠商品销量字段。销量继续显示“未提供”。App 数据来源及调用方式另行核验，不用想要人数、卖家累计成交或库存推算。
